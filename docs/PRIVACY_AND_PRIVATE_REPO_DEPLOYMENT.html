一、精準拆解 Claude 查核指出的兩大風險（事實核對）

⚠️ 風險 1：Commit History / 原始碼公開（Claude 判斷正確）

GitHub 個人免費帳號雖然可以建立無限個 Private 私有倉，但 GitHub Pages 免費版強制要求 Repo 必須為 Public（私有倉啟用 GitHub Pages 須付費升級 GitHub Pro $4/月）。

👉 只要使用 GitHub Pages 免費版，你的原始碼、歷史 Commit 與 PROMPT.md 就會對全球公開。

💡 風險 2：網頁輸入的資產持倉（取決於架構設計）

正確設計的網頁應用中，你在瀏覽器輸入的股票持倉存於本機 localStorage，永遠不會寫回 GitHub Repo！

👉 持倉會外洩只有三個原因：① 把真實股數/金額寫死在程式碼後 git push；② 存進無權限保護的公開資料庫；③ 個人後台沒加登入鎖。

三、五層縱深防禦架構（$0 零成本徹底防護）

防線 1｜徹底改用 Private GitHub Repo ＋ Cloudflare Pages Free

放棄需要 Public Repo 的 GitHub Pages，改讓 Cloudflare Pages 透過「單一 Repo 最小授權」拉取你的私有倉；私有倉每月仍內含 2,000 分鐘免費 GitHub Actions，盤後排程綽綽有餘。

防線 2｜程式碼與個人持倉 100% 分離（Zero Personal Data in Git）

Git 永遠只放假資料範例；真實持倉存於瀏覽器 localStorage / IndexedDB，跨裝置時透過前端 AES-256-GCM 密碼加密 JSON 檔或個人私有 Google Drive 匯出入；並用 .gitignore 與掃描器阻擋手滑提交。

防線 3｜網站入口加裝免費 Cloudflare Zero Trust Access 登入牆

在 Cloudflare 邊緣層開啟免費 Zero Trust（50 人內永久 $0），限定僅允許你的 Gmail / Email OTP 登入；未授權者連網頁原始碼與股價 API 都完全碰不到。

防線 4（備案）｜若堅持用 GitHub Pages 的雙倉隔離（Dual-Repo）

以 Private Repo 開發並保留完整 Commit History，再用 GitHub Actions 以單一無歷史的 Orphan Commit 將純編譯產物 dist/ 推到 Public Repo（但仍遠不如直接用 Cloudflare Pages + Private Repo 簡潔安全）。

防線 5（極致私人沙盒）｜完全不公開網址：維持現有 Google Drive 試算表版
